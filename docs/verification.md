## ما اختُبر فعلًا؟

1. `doctor --trace` جمع واجهات Windows والمسار الافتراضي، وفحص بوابته الخاصة، وسجّل تتبعًا محدودًا إلى أربع قفزات. أنشأ لقطة JSON وتقرير HTML وإيصال بصمات.
2. `selftest` بدأ مستمع HTTP مؤقتًا على `127.0.0.1` بمنفذ يختاره النظام؛ تحقق من TCP وHTTP 200، ثم تحقق من التقرير وبصماته وكشف تغيير بايت، وأعاد الملف وتحقق منه مجددًا. أوقف المستمع وفحص أن الاتصال الجديد به غير متاح.
3. أمر `probe` المستقل نجح مع خدمة اختبار مؤقتة أخرى، وأعاد رمز خروج 1 بعد إيقافها. لا تعمل خدمة الاختبار بعد انتهاء التجربة.
4. `plan` استُدعي من واجهة الأوامر على لقطة الشبكة الفعلية مع خدمة الاختبار أثناء تشغيلها. خرجت خطة **غير منفذة** وبقي الوصول الخارجي `NOT_TESTED`.
5. `report` أعاد بناء تقرير من لقطة محفوظة. `diff` على اللقطة نفسها أعاد عدم وجود تغيير. `verify` نجح مع تقريري الشبكة والخدمة.
6. `probe http://example.com/` رُفض قبل الاتصال، برمز خروج 2، لأن أداة الفحص في هذا الإصدار مخصصة لعناوين loopback وRFC1918 الرقمية.

تشمل الاختبارات الآلية الحالات التي قد تنتج استنتاجًا مضللًا: عنوان Tailscale لا يثبت CGNAT، ووجود IPv6 لا يثبت سماح firewall، وWAN المدخل يدويًا يبقى **supplied**، والعناوين المحجوزة لا تتحول إلى مرشحي نشر. تشمل أيضًا قيود HTTP والمهلة، وعدم اتباع إعادة التوجيه، وHTML escaping، وحقن أوامر التحكم في الطرفية، والألوان في الإخراج المحوّل، والعرض بعرض 40 عمودًا.

**تمييز مهم:** بعض قواعد التحليل والواجهة اختُبرت ببيانات fixtures. اختبارات HTTP استخدمت مستمعين حقيقيين مؤقتين. أمر `doctor` على Windows قرأ الشبكة الفعلية. لا يقوم أي من ذلك مقام فحص من شبكة خارجية.

## ما ظهر من البنية المنزلية؟

ظهرت واجهة Wi-Fi فعلية وبوابة خاصة، وواجهة Tailscale منفصلة. الفحص المحدود لمسار الاتصال أظهر عناوين خاصة ونطاق Shared Address Space. صفحة الجهاز الثاني استجابت بـ HTTP 200 وحملت علامة Huawei في محتواها؛ هذا **vendor hint**، وليس تحديدًا للطراز أو firmware.

لم تُقرأ صفحة WAN المصادق عليها، ولم يُحدد طراز TP-Link أو Huawei أو نمط تشغيلهما بصورة مستقلة. لذلك بقي عنوان WAN **UNKNOWN**، ولم تصدر الأداة حكمًا بأن CGNAT مؤكد أو أن الخدمة منشورة. المعرفات والعناوين التفصيلية متاحة في السجلات المحلية المذكورة أدناه.

## إعادة التشغيل

```powershell
cd D:\projects\HomeRouterLab-Neon-20261022
.\home-router.cmd --lang ar doctor --trace
.\home-router.cmd selftest
.\home-router.cmd verify reports\acceptance-20261022\network\receipt.json
```

لإنشاء دليل جديد مع تجربة قبول كاملة، استخدم اسم مجلد غير موجود:

```powershell
python scripts\acceptance.py --output reports\acceptance-next
```

إذا أردت حفظ فحص جديد فقط:

```powershell
.\home-router.cmd doctor --trace --output reports\new-check
```

الإخراج يرفض استبدال ملفات تقارير موجودة؛ اختر اسمًا جديدًا. `verify` يتحقق من تطابق البايتات مع الإيصال، ولا يثبت أصالة مستقلة أو صحة كل استنتاج إذا استُبدلت الملفات والإيصال معًا.
